## 一、时间线

### 1. Ollama 就位

- 执行 `ollama run qwen3:4b`，下载了 qwen3:4b（2.5 GB）
- 澄清概念：`ollama run` 启动了两层东西——终端里的**交互聊天**和后台**服务进程**（`localhost:11434`）。exit/`/bye` 只退出聊天，服务继续运行
- 实测：`11434` 在线（v0.30.10），已有 qwen3:4b、gemma3:4b、glm-ocr 三个模型
- 对 Open WebUI 的意义：后端启动不再有 Ollama 连接警告；前端模型下拉框可直接选本地模型，**无需任何 API key**——这是最快跑通全链路的路径

### 2. 前端包管理器选型：pnpm 被否决

- 问题：项目是 npm 管理，能否用 pnpm 启动前端？
- 结论：技术上能跑但不建议——仓库只有 `package-lock.json`（pnpm 无视它按 semver 重新解析 → 版本漂移）、pnpm v10 默认拦截 esbuild/cypress 构建脚本、严格 node_modules 有幽灵依赖风险、偏离官方与 CI 路径
- **过程中发现关键阻塞**：node v24.19.0 会被项目的 `engine-strict=true` + `engines <=22.x.x` 拦截，`npm install` 根本过不去 → 引出 node 22 安装需求

### 3. node 22 安装方式选型

- **zip + 系统 PATH**：可行。关键坑：Windows 有效 PATH = 系统变量在前 + 用户变量在后，node22 条目必须放**系统变量**并上移到 `C:\Program Files\nodejs` 之前 → 留作备选
- **Docker（nodejs.org 官方指引）**：否决——`--rm` 容器依赖不持久、挂载层破坏 Vite 热更新、容器/宿主机 node_modules 平台二进制冲突、cypress 不支持 alpine；官方那段是"体验 node"的通用指引，不是本项目开发工作流
- **fnm：采用** → 完整过程见 [node22安装排查记录.md](node22安装排查记录.md)

### 4. fnm 安装与三次排错（概要）

| 坑 | 现象 | 根因 | 修复 |
|---|---|---|---|
| 1 | `fnm use` 报"找不到环境变量" | Profile 只写没执行，当前 shell 没跑过 `fnm env` | 重开窗口或手动 eval |
| 2 | 新窗口 node 仍是 24 | `Add-Content` 把命令粘到上一行（无换行符 + 上行以 `#` 开头），整行静默成注释 | `Select-String` 定位后 notepad 拆行 |
| 3 | `fnm` is not recognized | 旧 VS Code 宿主开的新标签继承旧 PATH | 完全重启 VS Code |

- 最终：node v22.23.2 就位（fnm default），node 24 保留为 system

## 四、教训记录（本段新增）

- **"新标签页" ≠ "新进程"**：VS Code / Windows Terminal 不整体重启，就继承宿主启动时的旧 PATH
- **`Add-Content` 会粘行**：目标文件末尾无换行符时，新内容接到上一行；若上一行是注释，整行静默失效且不报错
- **选型要贴场景**：官方通用指引（用 Docker 跑 node）未必适合具体项目的开发工作流
- **engine-strict 是硬门槛**：node 版本不对，`npm install` 直接拒绝，任何镜像都救不了
